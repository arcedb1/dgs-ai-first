Leu os documentos de contexto do projeto (exercício completo, Anexo A, B e C) e montou o mapeamento por papel e etapa, salvo em "fluxo-ai-first-novatech.md":

Visão geral do fluxo:
- Claude (chat) — raciocínio, redação de specs/planos/tasks, análise crítica. Usado por todos os papéis, em todas as etapas.
- GitHub Copilot — geração de código e testes dentro do editor. Só entra a partir de Tasks/Implement, e só para Dev e Tech Lead.
- Claude Cowork — organização, tracking e checklists (papéis não-dev: DM, Product Specialist, QA).
- Claude Design — mockups de interface (Product Specialist, na etapa de Spec).
- Azure DevOps — board oficial de acompanhamento (todas as etapas, todos os papéis, mas quem escreve é DM/TL).
- GitHub — repositório e CI/CD (Implement → Deploy).

Mapa por papel e etapa:

Product Specialist:
- Spec: Claude (chat) escreve requirements.md; Claude Design gera mockup
- Plan: Claude (chat) esclarece dúvidas de escopo levantadas pelo TL
- Tasks: —
- Implement: Claude (chat) responde dúvidas ad hoc de escopo
- Review: Claude (chat) valida se o comportamento entregue respeita guardrails/spec
- Deploy: Claude (chat) faz smoke check pós-deploy contra a spec

Tech Lead:
- Spec: Claude (chat) revisa viabilidade técnica do requirements.md
- Plan: Claude (chat) escreve plan.md a partir do requirements.md + ADRs
- Tasks: Claude (chat) revisa/aprova tasks.md (Gate 2)
- Implement: GitHub Copilot para gerar/testar trechos de referência; Claude (chat) para AGENTS.md e skills
- Review: GitHub (PR/code review) + Copilot como apoio; Claude (chat) para revisão de arquitetura (Gate 3)
- Deploy: GitHub Actions/CI; aprovação final de deploy (Gate 4)

Desenvolvedor:
- Spec: —
- Plan: Claude (chat) para explorar abordagens técnicas
- Tasks: Claude (chat) converte plan.md em tasks.md; Copilot ajuda a quebrar em subtasks
- Implement: GitHub Copilot (geração de código) + Claude (chat) para debugging/arquitetura, com MCP (filesystem/git/memory)
- Review: GitHub Copilot para ajustar após comentários; Claude (chat) para refatorar
- Deploy: GitHub (merge, dispara CI/CD)

QA:
- Spec: Claude (chat) avalia se verification criteria são testáveis
- Plan: Claude (chat) inicia rascunho do test-plan.md a partir dos VCs
- Tasks: Claude (chat) finaliza cenários de teste; Claude Cowork organiza rastreabilidade teste→VC
- Implement: Claude (chat) escreve/revisa skill de geração de testes
- Review: Claude (chat) + Claude Cowork validam cobertura e suficiência dos testes (Gate 4)
- Deploy: Claude Cowork confirma sign-off de testes antes do deploy

Delivery Manager:
- Spec: Claude Cowork cria item de spec no board; Claude (chat) apoia definição de processo
- Plan: Claude Cowork atualiza status do board (Rascunho→Em Revisão); Azure DevOps
- Tasks: Azure DevOps cria work items a partir das tasks; Claude Cowork atualiza tracking (Gate 1/2)
- Implement: Azure DevOps monitora progresso; Claude Cowork sinaliza bloqueios
- Review: Claude Cowork mantém checklist de validation gates (Gate 3)
- Deploy: Azure DevOps + Claude Cowork fecham o ciclo (status "Validada")

Checkpoints humanos embutidos no fluxo:
1. Gate 1 — Spec → Plan: Product Specialist aprova o requirements.md antes do Tech Lead gerar o plan.md.
2. Gate 2 — Tasks → Implement: Tech Lead aprova o tasks.md antes do Dev iniciar a implementação.
3. Gate 3 — Code → Merge: Tech Lead faz code review humano; PR precisa de 1 aprovação.
4. Gate 4 — Tests → Deploy: QA valida cobertura e cenários de teste; Tech Lead aprova o deploy.

Sessão de brainstorming (skill /brainstorming, Fase 1 — Entendimento):
Pergunta 1: "Para começar o brainstorm: qual dimensão do fluxo você quer priorizar primeiro?"
Resposta: Papéis e responsabilidades

Pergunta 2: "O Tech Lead aprova os Gates 2, 3 e 4 sozinho. Qual risco de gargalo te preocupa mais?"
Resposta: Não é esse o problema

Pergunta 3: "Qual é o gargalo de papéis/responsabilidades que mais te preocupa nesse fluxo?"
Resposta: Dev sobrecarregado de decisão

Pergunta 4: "Quando os 2 devs divergem no uso do Copilot/quebra de tasks, qual consequência te preocupa mais?"
Resposta: Qualidade inconsistente

Fase 2 — Exploração de abordagens (apresentadas antes do usuário pedir para recomeçar):
Abordagem 1 (Recomendada) — Checklist de autovalidação por task no Cowork, ligado ao SKILL.md relevante.
Abordagem 2 — Par de revisão entre os 2 devs antes do Tech Lead.
Abordagem 3 — Reforçar as skills Domain/Artifact para reduzir variância no próprio Copilot.

O checklist deve incluir ao menos:
